# OMP 연결과 Knarr 패치

Knarr는 [Oh My Pi](https://github.com/can1357/oh-my-pi)의 RPC 실행 모드를 사용합니다. 모델 호출, 코딩 도구와 OMP 세션 처리는 OMP가 제공하며, Knarr는 프로젝트·이슈·승인·기록·화면·결과 처리 흐름을 구현합니다.

## 고정 버전

- 원본: OMP `v18.7.0`
- Knarr 실행 버전: `18.7.0-knarr.2`
- 원본·빌드 도구·네이티브 모듈·패치·바이너리 해시: `Runtime/OMP/manifest.json`
- 패치: `Runtime/OMP/prefix-replay.patch`
- 설치 시 검증: `scripts/install-omp.sh`
- 앱 실행 시 검증: `Sources/KnarrCore/OMP/OMPInstallation.swift`

체크섬 검증은 설치와 실행 양쪽에서 유지합니다. 임의의 PATH 실행 파일로 대체하지 않습니다.

## 패치의 목적

대화 재개 과정에서 제공자가 제외한 추론 블록 정보를 세션 기록과 함께 복원하도록 변경했습니다. 원본 서명 블록은 수정하지 않으며, 제외된 블록의 식별자는 해시로 보존하고 제공자·모델·자격증명 범위를 구분합니다.

또한 문맥 확장을 거쳐도 내용이 바뀌지 않은 메시지는 원래 객체를 복원해 불필요한 문맥 변경을 줄입니다. 패치에는 이 동작을 다루는 검사가 함께 들어 있습니다. 전체 변경은 패치 파일로 확인할 수 있습니다.

## 소스에서 재빌드

새 작업본과 macOS arm64 환경에서 실행합니다.

```sh
python3 scripts/build-patched-omp.py
```

원본과 고정된 도구를 내려받아 해시를 확인하고, 패치를 적용한 뒤 arm64·x64 바이너리를 빌드합니다. 빌드 경로·바이트코드·서명 차이로 실행 파일 해시가 달라질 수 있습니다. 스크립트는 차이를 출력하며 신뢰하는 해시를 자동 변경하지 않습니다.

다른 결과를 배포하려면 빌드 입력과 결과를 검토하고 관련 테스트를 실행한 뒤, manifest와 `OMPInstallation`의 값을 함께 갱신해야 합니다. 공개 릴리스 실행에는 해당 릴리스에 첨부된 검증된 바이너리를 사용합니다.

## RPC에서 구분하는 상태

- 요청 접수와 모델 작업 종료
- JSON 메시지 전송과 호스트 도구 실행 완료
- 모델 작업 중단과 실행 프로세스 종료
- 실행 결과 생성과 검증·반영 완료

요청에는 ID를 부여하고 이벤트 스트림으로 결과를 받습니다. 사람의 응답 대기는 수신 루프와 분리합니다. 앱 종료와 취소에서는 소유 프로세스의 종료도 확인합니다.

## 인증과 배포 고지

OMP의 인증은 OMP가 관리합니다. Knarr 소스나 릴리스에는 개발자의 로그인 정보가 포함되지 않습니다.

OMP 실행 파일을 배포할 때는 OMP `LICENSE`와 전체 `THIRD-PARTY-NOTICES.txt`를 함께 제공합니다. OMP 자체의 MIT 고지는 `docs/licenses/OMP-18.7.0-MIT.txt`에 있으며, 포함 구성요소의 라이선스는 각각 확인합니다. [외부 소프트웨어 고지](THIRD_PARTY_NOTICES.md)를 참고하세요.
