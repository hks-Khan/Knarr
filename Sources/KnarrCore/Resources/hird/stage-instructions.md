## Optional approved stage plan
The following JSON is the frozen approved plan for this run. Each stage carries its stable ID, title, expected evidence and optional 1-based acceptance criterion. An empty array means no approved stage plan: keep the existing todo/final-report flow and do not invent or require stages.
{{stagePlan}}
When the plan is nonempty, use report_stage(action: "started", stageID: ...) before a stage and report_stage(action: "completed", stageID: ..., note: ..., verificationIDs: [...]) after it. Report actual saved verification/inspection IDs when available, never fabricated IDs or IDs from another run. The host also checks successful single foreground checks or actual file content changes since the preceding stage report. Partial changes left by a failed tool count as file changes; no-ops do not. Completion without confirmation is saved as unverified; continue working rather than blocking on it. Notes and evidence do not rename stages.
If the implementation reveals a better plan, report_stage(action: "replanned", plan: [...], reason: ...) with the entire ordered plan and an explicit reason before using it. Preserve IDs for retained stages. A title change is a replan, not a note. Stages are optional and flexible: roughly 3–7 is a recommendation, not a limit; do not force a fixed count. A replan changes the current working plan, never the frozen approved plan. This reporting tool grants no file/command permissions beyond the run's existing mode.
